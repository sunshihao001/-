## 三、阶段 A：设计修补

### A1｜Skill 03 行为规则重写

**问题**：当前设计文件直接把 GMGN tags（smart_degen / sniper / bundler 等）当角色分类条件。但核心认知是「标签是别人的判断，行为规则是自己的判断依据」。两者矛盾。

**输入**：
- design/phase1-skill-03-wallet-roles.md（当前版本）
- learning/10.md（钱包角色理论）
- 认知基线第十九条（标签 vs 行为规则）

**输出**：
- design/phase1-skill-03-wallet-roles.md（修订版）
- 每个角色判定新增 `basis` 字段：`behavior_rule`（链上行为推断）/ `gmgn_hint`（GMGN 标签参考）/ `unverified`（数据不足）
- GMGN 标签从「分类条件」降级为「hint 参考」
- 新增 `UNABLE_TO_CLASSIFY` 状态：GMGN 数据不足以做行为判定时的默认输出
- 每个 GMGN 标签（smart_degen / sniper / bundler / rat_trader / fresh_wallet / dev）附四问审计

**验收条件**：
- [ ] 角色分类规则表每行有 basis 列
- [ ] 无任何角色判定仅依赖 GMGN tag
- [ ] UNABLE_TO_CLASSIFY 有明确触发条件
- [ ] 6 个 GMGN 标签各有四问（量什么/能伪/能算/本质）

**禁止**：
- 不删除 GMGN 标签字段（它们仍然有参考价值）
- 不把 basis=gmgn_hint 的角色当 behavior_rule 等级用

## 四、阶段 B：代码骨架

阶段 A 全部完成后才进入阶段 B。

### 技术选型

| 项 | 选择 | 原因 |
|----|------|------|
| 运行时 | Hermes Agent Skill | 和现有 Hermes 生态一致 |
| 语言 | Python | 设计文件伪代码都是 Python |
| Schema 验证 | jsonschema 或 pydantic | 强制输入输出格式 |
| 规则引擎 | 自写规则加载器 | 规则简单，不需要外部引擎 |
| GMGN 调用 | subprocess 调 gmgn-cli | 设计文件已定义命令映射 |
| 测试 | pytest + fixtures | fixture matrix 直接喂入 |
| 数据存储 | JSON 文件（data/runs/） | 设计文件已定义目录结构 |

### 每个 Skill 的标准目录结构

```
skills/meme-candidate-entry/
├── SKILL.md              # Hermes skill 定义文件
├── scripts/
│   ├── run.py            # 主入口
│   ├── schema.py         # 输入输出 schema 定义
│   ├── rules.py          # 判断/降级/阻塞规则
│   └── gmgn.py           # GMGN CLI 调用封装
├── tests/
│   └── test_candidate_entry.py
└── templates/
    └── report.md         # Markdown 报告模板（如有）
```

### B1｜公共模块

**输出**：
- skills/common/schema_base.py — 公共 handoff schema（evidence / counter_evidence / missing_fields / downgrade_reasons / blocker_reasons）
- skills/common/gmgn_client.py — gmgn-cli subprocess 封装
- skills/common/file_io.py — JSON 读写 + data/runs/ 目录管理
- skills/common/rule_loader.py — 从 rules/*.json 加载规则
- skills/common/phase_state.py — phase_state.json 读写

**验收条件**：
- [ ] schema_base 定义 BaseSkillOutput dataclass / pydantic model
- [ ] gmgn_client 封装了设计文件里的所有 GMGN 命令
- [ ] file_io 自动创建 data/runs/<token_address>/ 目录

## 六、禁止事项（贯穿全过程）

- 禁止调用任何交易 API（swap / sign / broadcast）
- 禁止使用真实私钥
- 禁止在代码中硬编码 GMGN API key
- 禁止输出「确定」「一定」「建议买入」等绝对结论
- 禁止跳过 fixture 验证直接宣称完成
- 禁止在 A 阶段未完成时开始 B 阶段代码
- Phase 1 最高只到 PAPER_ONLY，禁止实现 SEMI_AUTO / AUTO 路径
