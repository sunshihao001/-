GMGN 字节组合推理 — 提炼思路 / 思维模型 / 价值信息
============================================================
来源：37 L1 + 16 L2 推理链反向提炼
用法：这些不是「怎么算」，而是「为什么这么想」。可用于任何新数据源的推理。

============================================================
一、核心思维模型（8 个）
============================================================

模型 1：「五问题推理引擎」
---------------------------
任何字节组合，从五个问题开始：
  Q1: 我想知道什么市场事实？
  Q2: 这个事实在链上会留下什么痕迹？
  Q3: GMGN 哪个字段能看到这个痕迹？
  Q4: 单一字段够不够？不够和哪个配对？
  Q5: 配对后的值在什么范围内代表什么含义？

价值：把「凭感觉选指标」变成「按逻辑推导指标」。

---

模型 2：「三层分离」
---------------------------
Layer 0 (Canonical)：GMGN 给什么就是什么，不加工
Layer 1 (Feature) ：两个 raw 配对 = 一个有新含义的数值
Layer 2 (Structure)：N 个 feature 条件组合 = 一个市场状态判断

价值：每层有独立职责。L1 只产数值不产结论；L2 只产状态不产动作。
     防止「看到数字就直接决定买卖」。

---

模型 3：「反证法跨越」
---------------------------
L1 给你的是「SM 在买」「量在放大」这类事实。
L2 给你的是「SM 在有共识地积累」这类推断。
从事实到推断的桥梁是反证法：

  问：「如果这个结构不存在，数据长什么样？」→ 取反 → 就是判断条件。

  例：如果 SM 没在积累 → SM 方向分化、有的在出货、参与浅、没量
      所以「SM 积累」的条件 = 这四个反面的否定。

价值：把「我觉得是积累」变成「数据不支持不是积累」。
     后者可验证，前者不可。

---

模型 4：「归一化 = 选上下文」
---------------------------
大部分 L1 是 A/B 形式。B 不是随便选的——B 决定了你把 A 放在什么语境里看。

  选 liquidity 作分母 → 你把 A 放在「池子深度」里看
  选 holder_count 作分母 → 你把 A 放在「人均」里看
  选 volume_24h 作分母 → 你把 A 放在「近期常态」里看

规则：先问「我想把 A 放回什么上下文中解读」，
     那个上下文就是分母。

价值：同一个分子（如 buy_volume），不同分母产生完全不同的信息。
     选错分母 = 算出无意义的数字。

---

模型 5：「条件三层级」
---------------------------
每个 L2 结构候选有三层条件，不是平铺：

  required（AND）  → 缺一条就不成立。挑「定义性」特征。
  supporting       → 有更好，强化信心。挑「增强」特征。
  warning          → 任一条出现就推翻或降级。挑「否定」特征。

价值：结构判断不是 checklist 打勾，是「必要条件 + 增强 + 否决」三层。

---

模型 6：「三角验证」
---------------------------
一个可靠的结构判断至少跨越三个维度：

  方向（price/volume 方向）
  + 身份（谁在做：SM/KOL/dev/sniper/新人）
  + 背景（市场薄不薄/有没有操纵/dev 靠不靠谱）

只看方向不讲身份 → 不知道是 SM 进场还是新人在 FOMO
只看身份不讲背景 → 不知道 SM 是不是在薄市场里自买自卖
只看背景不讲方向 → 不知道健康市场里该做多还是做空

价值：任何单一维度的信号都不构成结构判断。

---

模型 7：「年龄上下文修正」
---------------------------
同一个数值，token 3 分钟大和 token 3 天大，含义完全不同。

  token < 5min → 几乎所有 L1 都不可靠
  token < 1h   → sniper 主导，需要修正解读
  token > 2h   → 数据开始有统计意义

价值：这不是一个 L1 feature，而是所有 L1/L2 的全局修正因子。
     新币的 rug_ratio 和 top_10_holder_rate 都不可信。

---

模型 8：「Allowed / Forbidden 边界」
-------------------------------------
每个 L2 结构候选必须同时定义：
  allowed：这个结构「可以说」什么
  forbidden：这个结构「不能说」什么

  例：L2-A1（SM 积累）
    allowed：「SM 群体买入意愿强于卖出意愿」
    forbidden：「这是买入信号」「价格一定上涨」

价值：防止下游消费者（gate / paper / 交易）把「结构描述」
     误解为「交易指令」。这是 VWAP 文档给的最重要方法论遗产。

============================================================
二、推理模式（5 种可复用）
============================================================

模式 1：比例归一
---------------------
场景：两个量需要比较，但绝对值在不同 token 间不可比。
方法：A / (A+B) 或 A / B
产出：buy_dominance, sm_penetration, mcap_to_liquidity_ratio 等
关键：分母的选择决定了解读框架（见模型 4）

---

模式 2：方向 × 规模
---------------------
场景：不仅要知道「买还是卖」，还要知道「是大单还是小单」。
方法：方向指标（buy_dominance）配对 规模指标（volume_per_swap）
产出 2×2 矩阵：
  大单+买入 → 鲸鱼/SM 进场
  小单+买入 → 散户 FOMO
  大单+卖出 → 大户离场
  小单+卖出 → 散户恐慌

---

模式 3：方向 × 身份
---------------------
场景：不仅要知道「买还是卖」，还要知道「谁在买谁在卖」。
方法：同一方向指标对不同的钱包标签分别计算。
产出：SM 方向 vs KOL 方向 → 共振 or 分歧
     SM 方向 vs sniper 方向 → SM 接盘 or 一起跑
     SM 方向 vs 新人涌入 → SM 建仓 or SM 出货给新人

---

模式 4：静态 × 动态
---------------------
场景：GMGN 给的大部分是静态快照（此刻的值）。
     需要配对动态变化（两次采样之差）。
方法：t1 采样 → 等待 → t2 采样 → 差值/时间
产出：holder_growth_rate, bonding_curve_progress_rate, volume_decay_ratio
限制：需要 cron job 或两次 API 调用

---

模式 5：排除法
---------------------
场景：不是检测「有什么」，而是检测「缺什么」。
方法：列出健康市场的必要条件 → 任一条不满足就是问题。
产出：L2-F1（健康市场）作为所有其他 L2 的前置过滤器。
     L2-C1/C2/C3 都是「排除后剩下的就是不健康」。
价值：检测「坏」比检测「好」更容易——坏有明确的硬指标。

============================================================
三、GMGN 环境特有的认知修正（5 条）
============================================================

修正 1：无 L1 订单簿
---------------------
GMGN 不提供 bid/ask/spread。所有 CEX 量化中的 spread 概念，
在 GMGN 中只能用池子储备比率 + fee_ratio 做代理。
精度远不如真实订单簿。

---

修正 2：已成交 ≠ 挂单
---------------------
buy_dominance 和 volume_per_swap 是基于「已成交」数据。
但 CEX 的 bid_ask_imbalance 是基于「挂单」数据。
前者反映「已经发生的」，后者反映「即将可能发生的」。
性质不同，不能直接套用 VWAP 文档中的 bid_ask_imbalance 概念。

---

修正 3：新币数据不可靠
---------------------
token < 5min 时：
  - rug_ratio 无意义（没有足够交易历史）
  - top_10_holder_rate 可能是 sniper bot，不代表庄家
  - ath_price = 开盘价，无参考价值
  - smart_degen_count 可能为 0（SM 还没来得及进场）
新币的所有 L1/L2 判断必须标注 DEGRADED 或推迟到 > 5min。

---

修正 4：Token 级别的 SM 数据 ≠ 钱包历史
----------------------------------------
GMGN 的 smart_degen_count 只统计「这个 token 上的 SM」。
不代表这些 SM 在其他 token 上的表现。
如果要评估 SM 质量，需要调 token holders 看 SM 的
total profit / win_rate 等历史数据。

---

修正 5：Meme 市场的极端值
-------------------------
Solana Meme 的 mcap/liquidity 可能高达 200+（CEX 不会出现）。
volume_intensity 可能高达 10+。
price_change_percent1h 可能高达 500%+。
标准 CEX 量化的阈值（如 spread > 0.1% = 异常）在这里不适用。
所有阈值必须用 Meme 市场数据重新校准。

============================================================
四、可直接迁移到其他数据源的方法
============================================================

1. 「五问题推理引擎」→ 任何新 API 字段都可以用同样方法推理
2. 「三层分离」→ 任何数据分析系统都可以拆成 Raw → Feature → Structure
3. 「反证法」→ 任何分类问题都可以用「不存在时长什么样」定义条件
4. 「条件三层级」→ 任何判断规则都可以拆成 required/supporting/warning
5. 「Allowed/Forbidden」→ 任何系统输出都应该明确「可以说/不能说」
6. 「年龄修正」→ 任何时间序列分析都应该有「数据成熟度」维度
7. 「三角验证」→ 方向+身份+背景，三维交叉验证

============================================================
五、一句话总结
============================================================

不是「这些字节能组合出什么」，
而是「我想知道什么市场事实 → 这个事实会留下什么痕迹 →
GMGN 哪个字段能看到 → 需要和谁配对 → 配对后在什么范围代表什么」。
这个顺序不能颠倒。
