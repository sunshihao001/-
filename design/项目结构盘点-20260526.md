# 缺口清单

## 高优先级

### 1. 6 个 skill 缺 `SKILL.md`

影响：

- Hermes skill 入口不完整。
- 虽有 scripts/tests，但不能作为完整 skill 被稳定调用。

建议：

- 从 `design/phase1-skill-01~06` 反推生成 `SKILL.md`。
- 每个 `SKILL.md` 只写：触发条件、输入、调用脚本、输出、禁止事项、验证方式。

## 中优先级

### 2. rules 覆盖度需要复核

影响：

- 判断逻辑可能散在代码里，不够透明。
- 你想要的“自然语言表达 → 稍微转成运行代码”会被破坏。

建议：

- 每个 skill 对应一个“自然语言判断规则”章节。
- 能抽成 JSON 的再抽。
- 不必为了规则化而过度工程化。

### 3. memory 过时

旧认知：

- “Phase 1 七个 skill 设计完成、代码未实现。”

当前事实：

- 7 个 skill 目录、scripts、tests 已存在。
- 6 个缺 `SKILL.md`。

## 低优先级

### 4. 大规模真实数据回测不足

当前 data/runs 里有 fixture / sample run。

是否要扩大真实数据测试，取决于下一阶段是否进入真实接口验证。

# 当前项目一句话

这是一个 **GMGN 接口驱动的 Solana meme paper-only 判断系统**。

核心不是复杂架构，而是：

1. 从 GMGN 接口拿字段。
2. 把字段组合成可解释的字节组合。
3. 用自然语言规则表达判断逻辑。
4. 把规则轻量转成代码。
5. 输出候选池、证据链、钱包结构、门控结论。
