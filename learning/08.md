# 08｜Rug Pull 技术实现：LP pull、mass dump、sell restriction 与 honeypot 风险

## 这一篇要解决的问题

这篇服务于 `Skill 02：meme-token-panel` 和 `Skill 06：meme-trade-gate`。

Rug pull 不是一个单一动作，它可以通过流动性、权限、持仓集中、卖出限制、协调砸盘等多种路径发生。系统要把这些路径拆成 evidence，而不是用一个“安全/不安全”的模糊标签覆盖。

## 正文

### 1. LP pull：流动性被抽走

LP pull 指流动性提供者撤走池子里的资金，使其他持有人很难卖出或只能以极差价格卖出。

字段反推四问：

- 量什么：量池子流动性是否稳定、是否由少数主体控制。
- 能伪：短时注入流动性可以制造安全假象。
- 能算：通过 liquidity、pool reserve、LP owner、历史流动性变化观察。
- 本质：LP 风险影响退出能力，是 trade gate 的重要风险证据。

### 2. mass dump：集中持仓砸盘

mass dump 指少数大户、部署者或关联钱包集中卖出，导致价格快速下跌。

它通常和 holder concentration、early buyer distribution、wallet roles 有关。Skill 02 只能记录持仓和市场事实，Skill 03/04 才能进一步判断钱包角色和结构。

字段反推四问：

- 量什么：量筹码是否集中在少数可行动主体手中。
- 能伪：地址分散可以伪装成去中心化。
- 能算：top holders、早期买入钱包、余额变化、卖出记录。
- 本质：mass dump 风险需要 wallet structure 验证。

### 3. sell restriction / honeypot 类风险

在 Solana meme 语境里，卖出限制可能来自权限、合约逻辑、池子设计、路由问题或交易异常。不同 token 标准和程序机制下表现不同，但系统不应该简单写“确定 honeypot”。

安全表达：

```text
疑似存在卖出限制证据，需进入 BLOCK 或 NEED_MORE_DATA。
```

### 4. Rug 风险如何进入系统

建议进入这些字段：

```text
evidence
counter_evidence
downgrade_reasons
blocker_reasons
missing_fields
confidence_score
```

避免进入：

```text
buy_signal
safe_token
guaranteed_rug
```

### 5. Skill 06 的使用方式

Trade gate 需要看多个风险证据是否形成链。

单个风险字段可能导致 `WATCH` 或 `NEED_MORE_DATA`；多个高权重风险共同出现，才适合 `BLOCK`。

## 小结

- Rug pull 可以通过 LP、权限、集中持仓、卖出限制等路径发生。
- Skill 02 记录事实，Skill 03/04 解释钱包，Skill 05 串证据，Skill 06 做 gate。
- 风险判断要写成 evidence chain，避免单字段定生死。
- 系统用“疑似”“证据等级”“需要补证据”，不用绝对结论。
