# 06｜GMGN 三个数据源机制：trending、trenches、signal 分别在量什么

## 这一篇要解决的问题

这篇服务于 `Skill 01：meme-candidate-entry`，也影响后续所有 skill 的数据入口认知。

候选入口需要知道 token 从哪里进入视野。GMGN 的 trending、trenches、signal 都能把 token 推到你面前，但它们量的是不同现象。入口来源只能解释“为什么看它”，不能直接解释“为什么可以交易”。

## 正文

### 1. trending：热度入口

`gmgn-cli market trending` 关注的是一段时间内更活跃、更显眼的 token。常见触发因素包括成交量、价格波动、买卖人数、资金流入速度、热度排序等。

它回答的问题是：

```text
哪些 token 正在被市场注意？
```

它不能回答：

```text
这个 token 的结构是否健康？
```

trending 很容易被短时间成交、刷量、少数钱包推动、社群集中喊单污染。它适合做候选发现，不适合做质量判断。

字段反推四问：

- 量什么：量市场注意力和近期活跃度。
- 能伪：成交量、买卖次数和价格波动都可以被协调交易制造。
- 能算：通过 GMGN trending 返回的排序、成交、价格、交易人数等字段间接观察。
- 本质：trending 是 entry_source，不是 gate decision。

### 2. trenches：新币入口

`gmgn-cli market trenches` 更接近新币 / 早期盘发现入口，尤其关注刚完成某些发行阶段、刚进入可交易环境、或处于早期活跃区间的 token。

它回答的问题是：

```text
哪些 token 刚进入值得观察的早期市场阶段？
```

它不能回答：

```text
这个 token 是否已经安全？
```

trenches 的价值在于早。它让系统看到候选池的源头，但早期也意味着数据少、结构未完成、钱包行为容易失真、池子稳定性不足。

字段反推四问：

- 量什么：量 token 是否处于早期可观察阶段。
- 能伪：早期交易可以由部署者、关联钱包、刷量脚本制造。
- 能算：通过 trenches 类型、完成状态、smart degen 数、时间窗口、池子信息观察。
- 本质：trenches 是早期发现入口，需要更强 missing_fields 和 downgrade 机制。

### 3. signal：行为触发入口

`gmgn-cli market signal` 通常根据某类市场行为或钱包行为触发，比如 smart money 买入、快速聚集、异常成交、某种策略标签命中。

它回答的问题是：

```text
哪些 token 出现了值得关注的行为模式？
```

它不能回答：

```text
这个行为模式是否可靠？
```

signal 听起来最像“信号”，也最容易被误读成买入理由。系统里必须把它降级为“行为线索”。它需要后续 wallet roles、wallet structure 和 evidence chain 验证。

字段反推四问：

- 量什么：量某类行为模式是否出现。
- 能伪：smart money 标签可能滞后，钱包可能被误标，少数钱包行为可能诱导市场。
- 能算：通过 signal_type、触发钱包、交易行为、时间窗口和后续钱包数据验证。
- 本质：signal 是 evidence seed，不是结论。

### 4. 三者进入系统后的正确位置

进入 `meme-candidate-entry` 后，这三者都只应该写入：

```text
entry_source
entry_reason
evidence.source
missing_fields（如字段不足）
downgrade_reasons（如来源风险高）
```

它们不能直接写入：

```text
gate_decision
PAPER_ONLY
buy_signal
confidence_score = 1.0
```

### 5. 对 Skill 01 的约束

Skill 01 可以根据 GMGN 来源解释为什么启动研究，但不能把来源解释为通过研究。

安全表达应该是：

```text
该 token 来源于 gmgn_trending，具备进入候选验证的理由。
```

避免表达：

```text
该 token 是 GMGN 热门，因此值得买。
```

## 小结

- trending 量市场注意力。
- trenches 量早期可观察候选。
- signal 量行为触发线索。
- 三者都只能作为 entry_source 或 evidence seed。
- 后续 gate 必须经过 token panel、wallet roles、wallet structure、evidence chain。
