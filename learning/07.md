# 07｜Solana Token 安全模型：mint、freeze、burn authority 在 Skill 02 里怎么用

## 这一篇要解决的问题

这篇服务于 `Skill 02：meme-token-panel`。

Token panel 不只展示价格、成交、流动性，还要读取安全相关字段。Solana token 的权限字段会影响后续风险判断，但这些字段需要作为风险证据，不能直接给出交易许可。

## 正文

### 1. mint authority

mint authority 代表谁还能继续增发 token。

如果 mint authority 仍然存在，供应量有继续扩大的可能。对 meme token 来说，这通常会进入风险项，因为额外增发可能稀释持有人，也可能配合分发或砸盘行为。

字段反推四问：

- 量什么：量供应量是否仍可被权限方改变。
- 能伪：权限状态可能需要从链上准确读取，前端展示可能滞后。
- 能算：通过 token security、mint account、authority 字段观察。
- 本质：mint authority 是风险 evidence，不是单独 gate。

### 2. freeze authority

freeze authority 代表是否有人能冻结账户转账。

它影响的是交易自由度。若 freeze authority 存在，某些账户理论上可能被限制转移 token。meme token 里这通常是高风险字段。

字段反推四问：

- 量什么：量账户转移自由度是否受权限控制。
- 能伪：前端可能不展示完整权限，或权限变化有延迟。
- 能算：通过 token security / mint metadata / SPL token account 信息观察。
- 本质：freeze authority 更接近 blocker 候选证据。

### 3. burn / ownership / blacklist 类风险

Solana token 风险不一定只来自 SPL 权限，也可能来自创建者行为、池子控制、合约扩展、转账限制、元数据混乱等。

Skill 02 的任务是把这些安全项作为结构化字段记录：

```text
security_flags
authority_status
liquidity_risk
holder_distribution
missing_fields
```

### 4. 安全字段的边界

安全字段不能直接说明 token 值得参与。

安全字段只回答：

```text
是否存在明显不能继续研究的基础风险？
```

如果安全字段缺失，应该进入 `missing_fields` 或 `NEED_MORE_DATA`。如果权限风险明确，应该进入 `blocker_reasons` 或 `downgrade_reasons`。

### 5. Skill 02 和后续 skill 的关系

Skill 02 给后续模块提供“事实面板”。

```text
Skill 02 输出事实和风险项；
Skill 03 分析参与钱包；
Skill 04 分析钱包关系；
Skill 05 汇总证据；
Skill 06 做门控判断。
```

如果 Skill 02 把“未发现权限风险”写成“安全”，后续 gate 会被污染。

## 小结

- mint authority 关注供应是否还能变化。
- freeze authority 关注账户转移自由度。
- 权限字段是风险 evidence，不是交易结论。
- 缺失安全字段必须写 missing_fields。
- Skill 02 只输出 token panel，不输出 gate decision。
