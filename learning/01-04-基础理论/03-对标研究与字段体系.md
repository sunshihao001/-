# 03｜对标研究：别人的字段体系和决策管道长什么样

## 这一篇要解决的问题

02 篇建立了 GMGN 入口、候选池、字段分 6 类、状态机、快做慢做分界。随后 spark 讨论抓取了 230+ GMGN 字段并收敛出 7 列词典方案。在动手做词典之前，先看看 meme 赛道里别人怎么组织字段、怎么分层、怎么做决策管道。用对标扩展思路，避免闭门造车。

## 正文

### 1. 对标对象和范围

这次对标不是找竞品，是找「做过类似事情的人，看他们的字段体系和决策结构」。

找到了 3 类对标：

- **开源 meme 分析工具**：GitHub 上有代码可读的项目
- **平台字段体系**：DexScreener / Birdeye / Nansen / Bubblemaps 暴露出来的数据模型
- **决策管道**：别人实际用的筛选流水线，有字段、有阈值、有门控

### 2. 开源对标 1：DexScreener Analysis Bot

**项目**：Immutal0/dexscreener-analysis-bot-meme（GitHub，TypeScript）

这个项目做了一件简单但完整的事：从 DexScreener 拿数据，过风险检查，输出候选。

#### 它的数据分两层

**原始层（TokenPair）**：
- `url, chainId, tokenAddress` — 标识
- `icon, header, openGraph, description` — 展示
- `links: [{type, url}]` — 社交
- `boosted: boolean` — DexScreener 付费推广标记

**派生层（InterestingToken）**：
- `reason: 'PUMP' | 'RUG' | 'TIER1' | 'CEX_LISTING'` — 4 级分类标签
- `metrics.priceChangePercent, volumeChange, liquidityChange, buyVsSellRatio`
- `timestamp`

两层很清楚：原始层只记事实，派生层才做判断。

#### 它的风险门控用硬编码阈值

```text
流动性：$10K ≤ liquidity ≤ $200K
成交量：volume_24h ≥ $500
价格变动：0% < priceChange < 2000%
社交评分：socialScore ≥ 1
```

#### 它的可疑活动检测用布尔门控

```text
liquidityToVolumeRatio < 0.1 → 拒绝（假量信号）
totalTxns < 10 && volume > $10K → 拒绝（少笔大额）
buyRatio > 0.95 || buyRatio < 0.05 → 拒绝（单向交易）
priceChange > 1000% → 拒绝（价格操控）
```

#### 它集成了 RugCheck

调用 `api.rugcheck.xyz`：
- `risks[].level === 'danger'` → 直接拒绝
- `score > 1000` → 高风险拒绝
- API 失败 → **默认不安全（fail-closed）**

**对我们的启发**：

- 字段分原始层和派生层，这和 spark 讨论的 L0/L1/L2 三层一致
- 风险门控用硬编码阈值 + 布尔组合，简单但有效
- RugCheck 集成的 fail-closed 策略值得学：API 超时就假定不安全
- 它没有钱包分析能力——这正好是 GMGN 比 DexScreener 多出来的维度

### 3. 开源对标 2：CryptOSINT（最重要发现）

**项目**：outerheaven199X/CryptOSINT（GitHub，TypeScript）

这是一个 Solana 代币 OSINT 工具，做了钱包分类 + 有机度评分。**和 SIKK 的钱包分析管道高度对齐。**

#### 它的钱包分 5 类

```text
WalletType = "AGENT" | "INSIDER" | "COPY" | "SNIPER" | "ORGANIC"
```

每一类有明确的判定规则：

**INSIDER**：
- 区块 0-1 进入
- 且（被 deployer 资助 或 持有供应量 > 1%）

**AGENT（机器人）**：
- 交易间隔标准差 < 2 秒且交易 > 10 笔
- 或与 Jito/MEV 程序交互
- MEV 程序地址硬编码

**SNIPER**：
- 区块 ≤ 3 进入且交易 ≤ 2 笔

**COPY（跟单）**：
- 区块 2-5 进入，交易 3-15 笔
- 跟单延迟 3-30 秒，标准差 < 5 秒，最少匹配 ≥ 2 次

**ORGANIC**：不满足以上任何条件

#### 它的钱包画像字段

```text
address
firstBlock — 相对于代币创建的首次出现区块
txCount
txTimestamps[] — 用于计算交易节奏标准差
totalBought / totalSold / currentHolding
isFundedByDeployer — 追踪 SOL 原生转账
interactsWithMev — 是否交互 Jito 程序
```

加上分类后的完整字段：

```text
address, type, pnlSol, pnlUsd, supplyPercent, entryBlock, txCount, tag
priorHistory?: PriorRecord[] — 跨代币历史
walletAge?
firstFunder? — 资金来源
firstFundAmountSol?
reputation?: ReputationScore
```

#### 它的信誉评分系统

```text
基础分：INSIDER=25, AGENT=10, SNIPER=8, COPY=3, ORGANIC=0
乘数：平均入场区块 < 2 → ×1.5
      钱包年龄 < 1 小时 → ×1.5
      资助 > 3 个下游钱包 → ×1.2
评级：CLEAN(0-10) | LOW(11-30) | MODERATE(31-55) | HIGH(56-80) | EXTREME(81-100)
```

#### 它的有机度评分

```text
organicScore = ORGANIC 钱包数 / 总钱包数 × 100

< 20% → CRITICAL（"价格行为基本是人为制造的"）
< 40% → HIGH
< 65% → MEDIUM
≥ 65% → LOW
```

#### 它的威胁类型体系

```text
ThreatType = "RUG" | "HONEYPOT" | "BUNDLE" | "AGENT_EXPLOIT" | "WHALE_SELL" | "INSIDER_MOVE" | "LARGE_BUY" | "LP_CHANGE"
ThreatSeverity = "CRITICAL" | "HIGH" | "MEDIUM"
```

**对我们的启发**：

- 钱包分类不靠标签名，靠行为规则：区块、时间、资金来源、交互程序
- 每个分类有明确阈值，可回溯、可验证、可质疑
- 有机度评分是一个简单但有用的代币级别指标
- 信誉评分用基础分 × 乘数，简单但可扩展
- GMGN 的标签（smart_degen, rat_trader 等）是黑箱的；CryptOSINT 的分类是透明的。这个差异很重要——我们的系统里，GMGN 标签只能做线索输入，不能做判断依据

### 4. 平台字段体系对标

#### DexScreener

- **原始字段**：chainId, tokenAddress, liquidity, volume, txns
- **派生字段**：priceChange（计算自 OHLCV）
- **标签字段**：boosted（付费状态，非链上数据）
- **无钱包分类能力**——纯市场数据层

#### Birdeye

- 比 DexScreener 多一个维度：`uniqueWallet24h`（独立钱包数）
- 多时间框架：`priceChange1h/4h/24h`，`traders_30m/1h/4h/24h`
- 仍然没有钱包标签系统——提供聚合统计但不分类单个钱包

#### Nansen

- **核心优势是钱包标签**：Smart Money / Fresh Wallet / Whale / Fund/VC / MEV Bot / Bridge User
- 标签基于历史行为概率模型
- 通常不暴露置信度给用户
- 和 GMGN 的标签一样是黑箱——但 Nansen 的标签经过更大规模验证

#### Bubblemaps

- 核心能力是**集群检测**：通过资金流向图谱将关联钱包分组
- 可视化暴露"伪分散"持仓（一个实体通过多钱包假装分散）
- 字段层面：持有者地址、持有比例、钱包间转账关系
- 派生指标：集中度分数、关联钱包簇大小

#### 平台对标总结

```text
            钱包标签  钱包分类规则  有机度  集群检测  市场数据  K线
DexScreener   ❌        ❌          ❌      ❌       ✅      ✅
Birdeye       ❌        ❌          ❌      ❌       ✅+     ✅
Nansen        ✅        ❌(黑箱)    ❌      ❌       ⚠️      ❌
Bubblemaps    ❌        ❌          ❌      ✅       ❌      ❌
GMGN          ✅        ❌(黑箱)    ❌      ❌       ✅      ✅
CryptOSINT    ❌        ✅(透明)    ✅      ❌       ❌      ❌
```

没有一个平台覆盖所有维度。SIKK 的工作流 OS 价值就在于把这些拼起来。

### 5. 决策管道对标

从对标项目提炼出一个行业标准的 meme 币筛选流水线：

```text
STAGE 1 — 安全门控（硬 REJECT）
├── RugCheck: danger risks → REJECT
├── Honeypot 检测 → REJECT
├── 合约风险: mint authority 未放弃 → REJECT
└── Bundle 检测: 供应集中 → REJECT

STAGE 2 — 市场指标门控（软 REJECT / WATCH）
├── 流动性范围: $10K-$200K
├── 成交量最低: $500
├── 买卖比例: 5%-95%
├── 价格波动: < 2000%
└── 独立钱包数（如有）

STAGE 3 — 钱包结构分析（WATCH / PAPER）
├── 有机度评分: > 40% → 继续
├── INSIDER 占比: < 20% → 继续
├── AGENT 占比: < 30% → 继续
├── 跟单网络: 密集度评估
└── 信誉评分: 顶级持有者 reputation < HIGH

STAGE 4 — 社交 / 叙事评估（PAPER / EXECUTE）
├── 社交平台覆盖: Twitter + Telegram
├── 描述质量验证
├── Boost 状态（付费推广）
└── 趋势热度

OUTPUT → REJECT / WATCH / PAPER / EXECUTE
```

和 02 篇建立的状态机对比：结构一致，但对标补了具体阈值和字段。

### 6. 对我们字段词典的启发

#### 分层方案升级

Spark 讨论分了 3 层（L0_raw / L1_derived / L2_label）。对标后建议分 5 层：

```text
L0_chain    — 链上原始值，可 RPC 验证（address, supply, balance）
L1_market   — DEX 聚合器计算值（price, volume, liquidity, txns）
L2_derived  — 平台加工指标，口径不透明（priceChange%, rug_ratio, hot_level）
L3_label    — 黑箱标签，判定规则未知（smart_degen, rat_trader, sniper）
L4_decision — 系统输出（REJECT / WATCH / PAPER / EXECUTE + confidence）
```

为什么要把 L0 拆成 chain 和 market？因为对标项目明确区分了链上事实（可验证）和市场数据（可观测但口径各异）。这两者的可信度不同。

#### 词典新增列

对标后，7 列词典方案可以加 2 列：

```text
原有：tier / source_of_truth / nullable / value_domain / evidence / consume_mode / traceable
新增：
  benchmark_comparison — 这个字段在对标项目里叫什么、怎么用
  fail_closed_behavior — 这个字段缺失时系统怎么办（默认安全 vs 默认通过）
```

`fail_closed_behavior` 是从 DexScreener Bot 的 RugCheck 集成学来的：API 超时就假定不安全。这个思路应该贯穿整个词典。

#### GMGN 标签的定位

对标后更清楚了：

- CryptOSINT 的钱包分类是**透明规则**：你知道为什么一个钱包被标成 INSIDER
- GMGN 的标签是**黑箱输出**：你不知道 smart_degen 的判定逻辑
- Nansen 的标签也是黑箱，但有更大规模的历史验证

所以 GMGN 标签在系统里的正确位置是：

```text
GMGN label → raw_evidence（保存）
           → canonical_wallet_label_hint（降级为线索）
           → 不能直接进入 structure_signal 或 strategy_gate
```

### 7. 对标后的行动清单

```text
1. 字段词典从 3 层改成 5 层（L0_chain / L1_market / L2_derived / L3_label / L4_decision）
2. 词典加 fail_closed_behavior 列
3. 词典加 benchmark_comparison 列
4. GMGN 标签字段统一降级为 hint，不做硬条件
5. 考虑引入 CryptOSINT 的透明分类规则作为钱包分析层的参考架构
6. 考虑引入有机度评分（organicScore）作为代币级别的结构指标
7. RugCheck 集成列入候选：fail-closed 外部安全检查
```

## 小结

1. meme 赛道里没有一个平台覆盖所有维度。SIKK 的价值在于把 GMGN（入口 + 标签线索）、CryptOSINT 式透明分类、Bubblemaps 式集群检测、DexScreener/Birdeye 市场数据拼成一条完整管道。

2. CryptOSINT 是最重要的对标发现。它的钱包分 5 类（INSIDER / AGENT / SNIPER / COPY / ORGANIC），每类有透明阈值，可回溯可质疑。GMGN 的标签做不到这一点。

3. 字段分层从 3 层升级到 5 层，核心区别是区分「链上可验证」和「市场可观测」，以及显式标出「决策输出层」。

4. fail-closed 是对标学到的关键工程纪律：字段缺失时默认不安全，而不是默认通过。

5. 下一步是带着这个 5 层分层 + 9 列词典方案，开始逐批手审 230+ 字段。
