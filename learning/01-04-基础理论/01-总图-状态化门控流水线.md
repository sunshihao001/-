# 01｜先把 Sol 交易工作流 OS 看成一条流水线

## 这一篇要解决的问题

这篇先解决一个基础问题：`Sol 交易工作流 OS` 到底是什么。先把它看成一条从候选 token 到交易许可的流水线，而不是一个抽象的大系统。

## 正文

`Sol 交易工作流 OS` 的核心对象是 Solana meme token。

它的工作不是一上来判断“买不买”。它的第一件事是把一个混乱的 token，放进一条固定流程里，让它一层一层接受检查。

这条流程可以先写成一句话：

```text
GMGN 候选 token
→ 风险过滤
→ 钱包分析
→ 钱包结构判断
→ 市场结构判断
→ 策略门控
→ paper / 半自动 / 自动执行
→ 止盈止损
→ 复盘接续
```

这就是工作流 OS 的基本形状。

### 1. GMGN 是入口

GMGN 在这里的角色是入口。

它帮系统拿到候选 token、热度、交易、标签、风险提示、钱包线索。系统不用从 Solana 全链原始数据开始扫，这样可以把第一版做轻。

但 GMGN 给出的 token 只是“进入候选池”。

候选池的意思是：这个 token 值得被检查。它还没有获得交易许可。

### 2. 第一层是风险过滤

进入候选池后，第一层处理的是安全问题。

这里关心的是：

- 能不能卖出；
- 有没有异常税；
- 有没有黑名单或权限风险；
- 流动性够不够退出；
- 持币是不是极端集中；
- 是否已经接近归零结构；
- 是否有明显出货末端特征。

这一层的输出可以很简单：

```text
REJECT：直接淘汰
NEED_CHECK：信息不足，补查
PASS_RISK_FILTER：通过安全过滤
```

这一步决定系统的底色。

一个好用的交易工作流，先擅长拒绝，再考虑执行。

### 3. 钱包分析是核心识别层

通过风险过滤之后，系统才进入钱包分析。

钱包分析关心的是：

- 谁早期买入；
- 钱从哪里来；
- 钱包之间是不是同源；
- 是否有吸筹、分发、接盘、出货路径；
- 有没有历史可疑地址复现；
- GMGN 标签是否支持这个判断。

这一层的输出不是“庄家确定存在”。

更合适的输出是：

```text
疑似结构钱包组
疑似同源地址
早期买入钱包
分发路径
出货风险
证据等级
置信度
降级原因
```

这样后面的模块能继续接，不会被一句模糊判断卡死。

### 4. 市场结构决定现在是否还有位置

钱包结构回答“谁在场内”。

市场结构回答“现在处于哪一段”。

常见阶段可以先粗分成：

- 启动；
- 拉升；
- 洗盘；
- 二波；
- 出货；
- 死亡反抽。

同一个 token，在不同阶段的交易意义完全不同。

早期结构好，不代表现在还能进。钱包看起来强，也不代表位置还值钱。市场结构这一层，就是为了阻止系统在错误的位置追进去。

### 5. 策略门控把判断变成许可

策略门控是整个 OS 的中枢。

它不写“我觉得可以买”。它只输出状态：

```text
REJECT
WATCH
TRACK
PAPER
SEMI_AUTO_READY
EXECUTION_READY
```

这些状态的意义是：

- `REJECT`：不要继续消耗注意力；
- `WATCH`：可以观察，不进入交易；
- `TRACK`：持续跟踪，等待结构变化；
- `PAPER`：可以纸面验证；
- `SEMI_AUTO_READY`：可以提醒人工确认；
- `EXECUTION_READY`：满足执行前置条件，但仍需要授权边界。

门控存在的意义，是把“分析”变成“是否允许进入下一步”。

### 6. Hermes 负责状态接续

这个系统运行在 Hermes 上，最大的价值是状态接续。

状态接续指的是：

- 这次查到哪一步；
- 哪些证据已经确认；
- 哪些字段缺失；
- 当前 token 是 `WATCH` 还是 `PAPER`；
- 下一次应该补查什么；
- 如果任务中断，回来能不能继续。

没有状态接续，系统就是一次性脚本。

有状态接续，它才像一个 OS。

### 7. 第一版先做到什么

第一版不需要追求全自动交易。

第一版先完成这个闭环：

```text
输入 GMGN 候选 token
→ 生成 token 事实包
→ 生成风险过滤结果
→ 生成钱包结构包
→ 生成市场结构判断
→ 生成策略门控状态
→ 写入 workflow_state
```

只要这条链稳定，后面的 paper、半自动、自动执行才有根基。

## 小结

- `Sol 交易工作流 OS` 是一条状态化门控流水线。
- GMGN 是入口，候选 token 不是买入信号。
- 第一层先做风险过滤，先排除归零和交易安全事故。
- 钱包结构和市场结构共同决定是否进入策略门控。
- Hermes 的关键作用是状态接续、回放和模块交接。
