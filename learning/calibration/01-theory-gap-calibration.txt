一、Calibration Summary
═══════════════════════════════════════════════════

GPT 的缺口扫描方向基本成立，但有三个系统性问题：

1. 知识粒度过细
   部分知识点（Solana 账户模型、SPL Token 标准）属于平台基础设施知识，
   不是本项目必须吃透的层级。需要的是「够用来做判断」的知识，
   不是「能写 Solana 开发教程」的知识。

2. 缺少「判断边界」维度
   GPT 列出了「需要学什么」，但没有标出「学到什么程度就够了」。
   每个知识点必须有停止条件。

3. Cross-skill gaps 优先级高于单 skill gaps
   GMGN 数据口径、token 生命周期、钱包身份推断——
   这三个贯穿全部 7 个 skill。应该先学这三个，再按 skill 顺序补细节。

二、Skill-by-skill Correction
═══════════════════════════════════════════════════

───────────────────────────────────────────────────
Skill 01：候选入口
───────────────────────────────────────────────────

GPT 判断：缺 token 生命周期、GMGN 候选来源、pump.fun / Raydium 机制

✅ 成立且优先：token 从 pump.fun 创建到 Raydium 上池的完整生命周期。
   整条流水线的输入源头。不懂这个，后面所有 skill 处理的数据都不知道在哪个阶段产生。

✅ 成立：GMGN trending / trenches / signal 三个数据源的差异。
   停止条件：能说出三者各自在 token 生命周期的哪个阶段最有用。
   不需要深入 GMGN 内部算法。

⚠️ 降级：pump.fun bonding curve 的数学公式。
   需要知道「bonding curve 阶段 token 还不在 DEX 上、流动性由公式决定、毕业后迁移到 Raydium」。
   不需要推导公式本身。

❌ 删除：Raydium AMM 底层实现细节（concentrated liquidity、tick 机制）。
   DEX 开发者知识，不是交易研究者知识。

停止条件：能对着一个真实 token 说出「它现在在生命周期的哪个阶段、
从哪个数据源进入候选池、为什么此时进入候选池是合理/不合理的」。

───────────────────────────────────────────────────
Skill 02：Token 面板
───────────────────────────────────────────────────

GPT 判断：缺 token 安全面板、流动性、holder、pool 风险知识

✅ 成立且优先：Rug pull 的技术实现方式。
   必须知道 4 种（LP pull / mass dump / sell tax / honeypot），
   Skill 02 的安全审计就是在检测这 4 种。

✅ 成立且优先：mint authority / freeze authority / burn 的含义。
   直接对应 Skill 02 的 renounced_mint / renounced_freeze_account 字段。

✅ 成立：LP 锁定 vs LP 销毁的区别。对应 burn_status 字段。

⚠️ 降级：流动性深度的数学模型。
   需要知道「流动性越低，价格越容易被操控，退出成本越高」。
   不需要计算 x*y=k 的滑点公式。

⚠️ 降级：holder 分布分析。更多属于 Skill 03/04 的范围。

❌ 删除：Solana 账户模型（rent、account size）。开发者知识。

停止条件：能对着 Skill 02 的 security 字段逐个说出
「这个字段在检测什么风险、风险的技术实现是什么、GMGN 这个值可信还是需要交叉验证」。

───────────────────────────────────────────────────
Skill 03：钱包角色
───────────────────────────────────────────────────

GPT 判断：缺钱包角色、smart money、sniper、dev wallet 等判断知识

✅ 成立，已有基础：CryptOSINT 5 类分类已学过。
   核心差距在于 GMGN 标签和行为规则之间的映射关系。

✅ 成立且优先：dev wallet 的识别逻辑。
   deployer 地址怎么找、fund_from 怎么追、creator_token_status 的几种状态各代表什么。
   Skill 03 最硬的知识点。

✅ 成立：Jito MEV 基本机制。
   停止条件：能判断一个钱包是否有 MEV bot 特征，不需要理解 Jito 技术架构。

⚠️ 降级：smart money 标签的统计学含义。
   GMGN 黑箱，无法验证内部逻辑。需要的是「为什么不能直接信任、怎么交叉验证」。

❌ 删除：KOL 钱包的社交影响力分析。营销知识，不是链上分析知识。

停止条件：能对着一个 token 的 Top 50 holders 列表，不看 GMGN 标签，
仅凭 start_holding_at、amount_percentage、native_transfer_from 三个字段，
说出哪些钱包疑似 INSIDER、哪些疑似 SNIPER、哪些无法判定。

───────────────────────────────────────────────────
Skill 04：钱包结构
───────────────────────────────────────────────────

GPT 判断：缺资金溯源、同源检测、协调买入、sybil 模式知识

✅ 成立且优先：同源资金检测的操作逻辑。
   native_transfer_from 相同 = 同一个资金来源。Skill 04 的核心功能。

✅ 成立且优先：协调买入的时间窗口分析。
   同一 5 分钟窗口内 ≥ 3 个钱包买入 = 疑似协调。阈值的含义和局限性必须理解。

✅ 成立：Sybil 攻击模式。一个实体拆成多个钱包假装分散持仓。

⚠️ 降级：多层资金溯源。GMGN 只提供 1 层 native_transfer_from。
   多层追踪属于 Phase 2。当前只需知道「1 层溯源能做什么、不能做什么」。

❌ 删除：图论算法（PageRank、Louvain 社区检测）。Phase 2+ 工程知识。

停止条件：能对着 Skill 04 的 same_source_groups 和 coordinated_buys 输出，
解释每一组的含义、置信度、和可能的误判场景。

───────────────────────────────────────────────────
Skill 05：证据链
───────────────────────────────────────────────────

GPT 判断：缺多信号融合、置信度计算、证据权重知识

✅ 成立：多信号融合的逻辑框架。
   需要理解「什么时候多个弱信号可以合成强判断、什么时候不能」。

⚠️ 降级：置信度计算的数学模型。
   设计文件里的公式是简单加减法。理解公式含义即可，不需要设计更复杂模型。

⚠️ 降级：贝叶斯更新。04 篇已提过。当前不需要实现。

❌ 删除：统计学假设检验框架。
   学术知识，对 meme 币场景不实用。数据量小、噪声大、生命周期短，经典统计前提不成立。

停止条件：能对着 Skill 05 的 6 个 signal（SM 方向、结构风险、Dev 状态、
Wash trading、价格-行为背离、Fresh wallet 占比），
逐个说出「这个信号在什么情况下可信、什么情况下会误导」。

───────────────────────────────────────────────────
Skill 06：门控
───────────────────────────────────────────────────

GPT 判断：缺阈值来源、门控 vs 策略边界、downgrade 逻辑

✅ 成立且优先：门控 vs 策略的边界。
   门控回答「允不允许」，策略回答「怎么做」。当前系统只有门控，没有策略。

✅ 成立：阈值来源。
   rug_ratio > 0.5、liquidity < $10K 等来自对标研究，是经验值不是精确值，可以调。

✅ 成立：downgrade 逻辑。
   数据不足时不是 BLOCK，是降级继续。对 meme 币场景很关键，大部分 token 数据不完整。

❌ 删除：门控规则的自动优化/机器学习方法。Phase 3+ 的事。

停止条件：能对着 Skill 06 的规则表（G01-G06 一票否决、G10-G12 观察、G20-G22 正向），
逐条说出「这条规则在防什么、阈值从哪来、什么情况下会误判」。

五、Forbidden Misinterpretations
═══════════════════════════════════════════════════

以下知识只能作为研究，学完后禁止变成买入信号或执行依据：

  1.「这个 token 安全审计全通过」≠ 可以买
    安全审计只排除技术风险，不判断市场风险。

  2.「smart money 在买」≠ 跟着买
    smart money 标签是 GMGN 黑箱，不知道判定逻辑、不知道是否被利用做诱饵。

  3.「有机度 > 65%」≠ 安全
    有机度只衡量持有者组成，不衡量市场阶段。有机度高的 token 照样可能在出货末端。

  4.「没有同源资金组」≠ 没有庄家
    聪明庄家用 CEX 中转，1 层溯源追不到。

  5.「门控输出 PAPER_ONLY」≠ 系统建议你交易
    PAPER_ONLY = 可以用纸面模拟记录判断对错，不是可以下单。

  6.「置信度 0.85」≠ 85% 的概率赚钱
    置信度衡量的是当前证据的完整程度，不是交易成功的概率。

  7. 任何学习文章里出现的阈值（$10K 流动性、0.5 rug_ratio、40% 有机度）
     都是经验参考值，不是物理常数。可以调、应该调、必须在实战中校准。
