## 你读完之后需要理解的关键点

1. **执行流**：candidate-entry → token-panel → wallet-roles → wallet-structure → evidence-chain → trade-gate，由 workflow-controller 串联
2. **数据源**：所有链上数据通过 gmgn-cli 工具采集，每个 skill 设计文件里有完整的命令映射
3. **输出规范**：每个 skill 输出一个 JSON 文件，schema 在 phase0 契约里定义公共字段，每个 skill 文件里定义专属字段
4. **状态管理**：每个 token 分析任务有一个 phase_state.json，记录当前阶段、已完成阶段、阻塞信息
5. **安全边界**：Phase 1 只做研究，最高门控到 PAPER_ONLY，禁止真实交易、禁止绝对性措辞
6. **数据存储**：每个 token 的运行数据在 /root/sikk-gmgn/data/runs/<token_address>/ 下

## 注意事项

1. **不要改设计**：设计文档是已确认的，按设计执行，不要自己重新设计
2. **不要跳步**：6 个 skill 有严格的前后依赖，不能跳过
3. **不要越权**：controller 不做业务判断，每个 skill 只做自己范围内的事
4. **字段不能编造**：API 没返回的数据放 missing_fields，不填默认值
5. **措辞规范**：所有结构判断用"疑似"、"候选"、"证据等级"，不用"确定"、"一定"
6. **目录规范**：代码放 /root/sikk-gmgn/skills/ 下对应目录，数据放 /root/sikk-gmgn/data/，不要在其他地方建文件
7. **运行环境**：系统运行在 Hermes Agent 上，利用 Hermes 的 skill 系统、cron、Telegram gateway、memory、delegation
